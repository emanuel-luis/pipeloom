    Tested models¶

    Check what a transformation does before it writes anything. This example is a small revenue pipeline: orders in several currencies, refunds and daily exchange rates become net revenue in US dollars per day. Three models carry logic worth testing: a currency conversion with a join, a refund netting with an aggregate and a join, and a daily total with a window.

    The project is examples/tested_models. It runs on DuckDB (the default target) and on polars.

    The models¶

    Each model is a portable function (frame_api="narwhals"), so the same code runs on both engines. See Portable models.

    @model(
    frame_api="narwhals",
    inputs={"orders": source("shop", "orders"), "fx_rates": source("shop", "fx_rates")},
    expectations=[
        Expectation(name="rate_found", check=not_null("amount_usd"), on_violation="fail")
    ],
)
def orders_usd(ctx, orders, fx_rates):
    """Drop cancelled orders and convert the rest with the rate of the order date."""
    return (
        orders.filter(nw.col("status") != "cancelled")
        .join(
            fx_rates,
            left_on=["order_date", "currency"],
            right_on=["rate_date", "currency"],
            how="left",
        )
        .with_columns((nw.col("amount") * nw.col("rate")).round(2).alias("amount_usd"))
        .select("order_id", "order_date", "customer_id", "rate", "amount_usd")
    )

    @model(
    frame_api="narwhals",
    inputs={"orders_usd": ref("orders_usd"), "refunds": source("shop", "refunds")},
)
def net_revenue(ctx, orders_usd, refunds):
    """Subtract the refunds of each order, converted at the rate of the order."""
    refunded = refunds.group_by("order_id").agg(nw.col("refund_amount").sum().alias("refunded"))
    return (
        orders_usd.join(refunded, on="order_id", how="left")
        .with_columns(nw.col("refunded").fill_null(0.0))
        .with_columns(
            (nw.col("amount_usd") - (nw.col("refunded") * nw.col("rate")).round(2)).alias("net_usd")
        )
        .select("order_id", "order_date", "customer_id", "amount_usd", "net_usd")
    )

    @model(frame_api="narwhals", inputs={"net_revenue": ref("net_revenue")})
def daily_revenue(ctx, net_revenue):
    """Orders and net revenue per day, with a running total."""
    daily = net_revenue.group_by("order_date").agg(
        nw.col("order_id").count().alias("orders"),
        nw.col("net_usd").sum().round(2).alias("net_usd"),
    )
    return daily.with_columns(
        nw.col("net_usd").cum_sum().over(order_by="order_date").round(2).alias("running_net_usd")
    )

    Unit tests¶

    A unit test gives a model rows and says which rows it must return. It builds the inputs in memory and writes nothing. The cases live in the properties file, next to the model.

      - name: orders_usd
    description: Orders in US dollars, cancelled orders removed.
    unit_tests:
      - name: converts_with_the_rate_of_the_day
        given:
          orders:
            rows:
              - order_id: 1
                order_date: 2026-03-01
                customer_id: c1
                currency: EUR
                amount: 50.0
                status: paid
              - order_id: 2
                order_date: 2026-03-02
                customer_id: c1
                currency: EUR
                amount: 50.0
                status: paid
              - order_id: 3
                order_date: 2026-03-01
                customer_id: c2
                currency: USD
                amount: 10.0
                status: cancelled
          fx_rates:
            rows:
              - rate_date: 2026-03-01
                currency: EUR
                rate: 1.10
              - rate_date: 2026-03-02
                currency: EUR
                rate: 1.20
        expect:
          rows:
            - order_id: 1
              amount_usd: 55.0
            - order_id: 2
              amount_usd: 60.0
    data_tests:
      - name: order_id_unique
        check:
          unique: [order_id]

    net_revenue reads its refunds from a CSV file, and daily_revenue reads both its input and its expected rows from CSV. CSV dates must be declared, so those cases list columns.

      - name: net_revenue
    description: Net revenue per order, refunds subtracted.
    unit_tests:
      - name: refunds_are_netted
        given:
          orders_usd:
            rows:
              - order_id: 1
                order_date: 2026-03-01
                customer_id: c1
                rate: 1.10
                amount_usd: 110.0
              - order_id: 2
                order_date: 2026-03-01
                customer_id: c2
                rate: 1.0
                amount_usd: 40.0
          refunds:
            csv: tests/data/refunds.csv
            columns:
              - name: refund_amount
                dtype: float64
        expect:
          rows:
            - order_id: 1
              net_usd: 77.0
            - order_id: 2
              net_usd: 40.0
    data_tests:
      - name: order_exists
        check:
          relationships:
            column: order_id
            to:
              ref: orders_usd
            field: order_id

      - name: daily_revenue
    description: Orders and net revenue per day, with a running total.
    unit_tests:
      - name: running_total_follows_the_date
        given:
          net_revenue:
            csv: tests/data/net_revenue.csv
            columns:
              - name: order_date
                dtype: date
              - name: net_usd
                dtype: float64
        expect:
          csv: tests/data/daily_revenue.csv
          columns:
            - name: order_date
              dtype: date
            - name: net_usd
              dtype: float64
            - name: running_net_usd
              dtype: float64
    data_tests:
      - name: one_row_per_day
        check:
          unique: [order_date]

    Run the tests¶

    $ uv run pipeloom test --project-dir examples/tested_models
PASS   daily_revenue: running_total_follows_the_date
PASS   net_revenue: refunds_are_netted
PASS   orders_usd: converts_with_the_rate_of_the_day
unit tests: 3 passed, 0 failed

    Exit code 0. Nothing was written and no run was recorded. Add --target polars to run the same cases on polars.

    Build¶

    pipeloom build runs the unit tests of the selected models first. If one fails it stops with exit 1 before a run id exists. When they pass it runs the models, then the data tests of each model after its write.

    $ uv run pipeloom build --project-dir examples/tested_models
unit tests: 3 passed, 0 failed
1/3 OK     orders_usd ............. table/overwrite        9 rows
2/3 OK     net_revenue ............ table/overwrite        9 rows
3/3 OK     daily_revenue .......... table/overwrite        3 rows

    The data tests are unique on order_id and on order_date, and a relationships check that every net_revenue.order_id exists in orders_usd. Their results are in target/run_results.json, as entries of results[].expectations with scope: table. The model also has an expectation, rate_found, which judges each batch before it is written (scope: batch).

    When the logic is wrong¶

    Suppose someone changes the conversion to divide by the rate instead of multiplying:

    -        .with_columns((nw.col("amount") * nw.col("rate")).round(2).alias("amount_usd"))
+        .with_columns((nw.col("amount") / nw.col("rate")).round(2).alias("amount_usd"))

    pipeloom test now fails with PLX114 and a row diff. Lines starting with - are expected rows the model did not return, lines starting with + are rows nobody expected:

    FAIL   orders_usd: converts_with_the_rate_of_the_day PLX114 2 missing, 2 unexpected row(s)
       - {"order_id": 1, "amount_usd": 55.0}
       - {"order_id": 2, "amount_usd": 60.0}
       + {"order_id": 1, "amount_usd": 45.45}
       + {"order_id": 2, "amount_usd": 41.67}
unit tests: 2 passed, 1 failed

    Exit code 1. pipeloom build stops at the same point, so the wrong numbers never reach a table. The example does not commit the broken model: the CI test applies this edit to a copy in a temporary directory.

    Plain pytest¶

    A decorated function is still a function. A portable model takes frames, so a test can wrap a polars frame, pass None for ctx and check the rows. This is the fastest loop and needs no project run.

    def test_orders_usd_drops_cancelled_orders():
    orders = frame(
        {
            "order_id": [1, 2],
            "order_date": ["2026-03-01", "2026-03-01"],
            "customer_id": ["c1", "c2"],
            "currency": ["USD", "USD"],
            "amount": [10.0, 99.0],
            "status": ["paid", "cancelled"],
        }
    )
    fx_rates = frame({"rate_date": ["2026-03-01"], "currency": ["USD"], "rate": [1.0]})
    out = rows(revenue.orders_usd(None, orders, fx_rates))
    assert [(r["order_id"], r["amount_usd"]) for r in out] == [(1, 10.0)]

    $ uv run pytest examples/tested_models/tests

    What to try next¶

    • Add a case for a missing exchange rate and watch the rate_found expectation fail.
    • Add a refund for an order that does not exist and see the order_exists data test report it.
    • Move the cases to their own folder, as in Testing models.
    • Run pipeloom build --select daily_revenue, which runs only that model's unit tests first.

    The CI test for this page is tests/examples/test_walkthrough_tested_models.py.
