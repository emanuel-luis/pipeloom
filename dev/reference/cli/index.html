    Command line¶

    pipeloom init¶

    pipeloom init [DIRECTORY] creates a project, like dbt init. DIRECTORY defaults to a new folder named after the project in the current directory.

    • When stdin is a terminal it asks for what the flags leave out: the project name (default: the directory name), the engine (polars, pandas, spark or databricks, default polars) and, on databricks, the Unity Catalog catalog (default main). Otherwise, or with --no-input, it uses the flags and those defaults.
    • polars, spark and databricks get SQL models; pandas gets Python models under src/. polars, pandas and spark read a small CSV in data/, so pipeloom run works right away on polars and pandas. databricks reads samples.tpch.orders and comes with a state table, an artifacts volume and a serverless deploy block; the comments in pipeloom.yml say what to create before pipeloom databricks deploy.
    • A directory that is not empty needs --force. Existing files are never overwritten: they are kept and listed as skipped. A directory that already holds pipeloom.yml is refused.
    • Exit codes: 0 on success, 2 on a usage error (bad name or engine, --catalog without databricks, an existing project, a non-empty directory without --force).

    pipeloom new model¶

    pipeloom new model NAME adds one model file to a project and prints the paths it wrote.

    • The file is models/<folder>/<NAME>.yml: the schema modeline and one block-style entry. --folder is relative to the first model path and cannot leave it.
    • --sql writes a select 1 as id body. --python writes python: <project>_models.<NAME>:build and a stub build(ctx, **inputs) under the first python_paths entry, which must be set explicitly in pipeloom.yml. Without a flag, pandas default targets get Python and the rest SQL.
    • Exit codes: 0 on success, 1 when the project does not load, 2 on a usage error (bad name, a name or file that exists, --sql with --python, a folder outside the model path, no python_paths).

    pipeloom¶

    pipeloom: declarative, engine-agnostic data pipelines in YAML.

    Usage:

    pipeloom [OPTIONS] COMMAND [ARGS]...

    Options:

      --version  Show the version and exit.
  --help     Show this message and exit.

    pipeloom compile-¶

    Validate the project and write the plan to a manifest file.

    Usage:

    pipeloom compile- [OPTIONS]

    Options:

      --project-dir DIRECTORY    Directory that holds pipeloom.yml.  [default: .]
  --vars TEXT                Variables as a YAML or JSON mapping; they
                             override the vars block.
  --target TEXT              Target to bind; default_target or the only target
                             when omitted.
  --plugin MODULE:ATTR       A PluginSpec to load besides the installed
                             plugins. Repeatable.
  -s, --select SELECTOR      Models to include: name, tag:x, path:dir,
                             materialized:x, +model, model+, N+model, model+N.
                             Space unions, comma intersects. Repeatable, all
                             are unioned.
  --exclude SELECTOR         Remove the models this selector matches from the
                             selection. Repeatable.
  --state DIR                Folder of a reference manifest.json (and
                             optionally run_results.json), for the state: and
                             result: selectors. Relative to the project dir
                             unless absolute. `compile --stable` or the
                             artifacts root (target) both work.
  --log-format [text|json]   Diagnostics and events on stderr: readable text
                             or one JSON object per line.  [default: text]
  --boundary [process|task]  Where units run; default is the target's boundary
                             (process).
  --out PATH                 Manifest file, relative to the project dir unless
                             absolute.  [default: target/manifest.json]
  --stable                   Blank generated_at, invocation_id and the
                             selection so the same project and target always
                             give the same bytes. `run --manifest` then runs
                             every model unless --select or --exclude is
                             given.
  --warn-error               Exit 1 on warnings too.
  --help                     Show this message and exit.

    pipeloom explain¶

    Print what a diagnostic CODE means, for example PLX101 (case-insensitive).

    Shows the title, layer, severity, status, the version the code appeared in, the explanation and the link to the error-code page. Reads no project.

    Usage:

    pipeloom explain [OPTIONS] CODE

    Options:

      --help  Show this message and exit.

    pipeloom finalize¶

    Merge the unit results of a run into run_results.json and close the run.

    Units in scope (default: the whole plan) take their attempt file, else the state given with --unit-states or --unit-states-json, else they are skipped as not_run, which does not fail the run. A unit marked excluded gets no row. Exit codes: 0 ok, 1 a unit failed, 2 bad usage, 130 cancelled. Running it again rewrites the same results.

    Usage:

    pipeloom finalize [OPTIONS]

    Options:

      --project-dir DIRECTORY      Directory that holds pipeloom.yml.  [default:
                               .]
  --vars TEXT                  Variables as a YAML or JSON mapping; they
                               override the vars block.
  --target TEXT                Target to bind; default_target or the only
                               target when omitted.
  --plugin MODULE:ATTR         A PluginSpec to load besides the installed
                               plugins. Repeatable.
  -s, --select SELECTOR        Models to include: name, tag:x, path:dir,
                               materialized:x, +model, model+, N+model,
                               model+N. Space unions, comma intersects.
                               Repeatable, all are unioned.
  --exclude SELECTOR           Remove the models this selector matches from
                               the selection. Repeatable.
  --log-format [text|json]     Diagnostics and events on stderr: readable text
                               or one JSON object per line.  [default: text]
  --run-id TEXT                The run to close: the run id every unit
                               invocation used.  [required]
  --manifest FILE              Use the plan of this manifest instead of
                               compiling the project.
  --expect-plan-hash HEX       Stop with PLX103 unless the plan hash is this
                               sha256.
  --unit-states PATH           A JSON file, schema pipeloom.unit_states/1,
                               with what the orchestrator knows about units
                               that wrote no attempt file: {unit_id: {status:
                               skipped|cancelled|failed|excluded, reason,
                               code, message, orchestrator_ids}}.
  --unit-states-json TEXT      The same document as --unit-states, given
                               inline (for an orchestrator that cannot share a
                               file). Not together with --unit-states.
  --orchestrator-id KEY=VALUE  An id the orchestrator gave this run, such as
                               job_run_id=42. It goes into the attempt files,
                               the run results and the context of every event.
                               Repeatable; a later duplicate wins. Key:
                               [a-z][a-z0-9_]{0,63}; value: 1 to 256 printable
                               characters.
  --run-started-at ISO8601     Start time of the run, with a UTC offset. A run
                               that recorded its start keeps it.
  --help                       Show this message and exit.

    pipeloom init¶

    Create a project in DIRECTORY (default: a new folder named after the project).

    When stdin is a terminal and --no-input is not given, asks for the values the flags leave out: the project name, the engine and, on databricks, the catalog.

    Usage:

    pipeloom init [OPTIONS] [DIRECTORY]

    Options:

      --name TEXT                     Project name. Default: the directory name.
  --engine [polars|pandas|spark|databricks]
                                  Engine of the dev target. Default: polars.

  --no-input                      Never prompt: use the flags and the
                                  defaults.
  --force                         Allow a directory that is not empty.
                                  Existing files are kept, never overwritten,
                                  and listed as skipped.
  --help                          Show this message and exit.

    pipeloom retry¶

    Run again what a finished run did not finish. Exit codes as run; 1 also for PLX113.

    Selects the units of run RUN_ID that failed, timed out, were skipped or were cancelled, and runs them in a new run that records RUN_ID as its parent. The project is compiled again, so a fixed model is picked up. The retry inherits the vars (--vars wins), --full-refresh, --state and --defer of the run it retries.

    Usage:

    pipeloom retry [OPTIONS]

    Options:

      --project-dir DIRECTORY         Directory that holds pipeloom.yml.
                                  [default: .]
  --vars TEXT                     Variables as a YAML or JSON mapping; they
                                  override the vars block.
  --target TEXT                   Target to bind; default_target or the only
                                  target when omitted.
  --plugin MODULE:ATTR            A PluginSpec to load besides the installed
                                  plugins. Repeatable.
  --log-format [text|json]        Diagnostics and events on stderr: readable
                                  text or one JSON object per line.  [default:
                                  text]
  --from RUN_ID                   The finished run to retry: its failed,
                                  skipped and cancelled units run again.
                                  [required]
  --run-id TEXT                   Name of the new run; it must differ from
                                  --from. Default: a timestamp and a suffix.
  --full-refresh / --no-full-refresh
                                  Rebuild append tables from scratch. Default:
                                  what the retried run did.
  --orchestrator-id KEY=VALUE     An id the orchestrator gave this run, such
                                  as job_run_id=42. It goes into the attempt
                                  files, the run results and the context of
                                  every event. Repeatable; a later duplicate
                                  wins. Key: [a-z][a-z0-9_]{0,63}; value: 1 to
                                  256 printable characters.
  --fail-fast                     After the first failure, start no more
                                  units.
  --no-lock                       Do not take the run lock.
  --workers INTEGER RANGE         Units to run at once. Default: the target's
                                  setting, else min(4, CPUs).  [x>=1]
  --boundary [process|task]       process runs units on threads here; task
                                  runs each in its own process. Default: the
                                  target's boundary.
  --warn-error                    Exit 1 on warnings too.
  --cancel-grace DURATION         After a stop request (Ctrl+C, SIGTERM) or a
                                  timeout, how long running units may finish
                                  before they are killed, as 30s, 2m or 30.
                                  Default: the setting, else 30s.
  --help                          Show this message and exit.

    pipeloom run¶

    Run the selected models. Exit codes: 0 ok, 1 a unit or a check failed, 2 bad usage, 130 stopped.

    The first Ctrl+C or SIGTERM stops starting units and gives running ones --cancel-grace to finish; a second one kills them at once; a third raises KeyboardInterrupt.

    -s unit:NAME runs one unit without a lock or run results, and never retries it; the process executor uses it.

    Usage:

    pipeloom run [OPTIONS]

    Options:

      --project-dir DIRECTORY      Directory that holds pipeloom.yml.  [default:
                               .]
  --vars TEXT                  Variables as a YAML or JSON mapping; they
                               override the vars block.
  --target TEXT                Target to bind; default_target or the only
                               target when omitted.
  --plugin MODULE:ATTR         A PluginSpec to load besides the installed
                               plugins. Repeatable.
  -s, --select SELECTOR        Models to include: name, tag:x, path:dir,
                               materialized:x, +model, model+, N+model,
                               model+N. Space unions, comma intersects.
                               Repeatable, all are unioned.
  --exclude SELECTOR           Remove the models this selector matches from
                               the selection. Repeatable.
  --state DIR                  Folder of a reference manifest.json (and
                               optionally run_results.json), for the state:
                               and result: selectors. Relative to the project
                               dir unless absolute. `compile --stable` or the
                               artifacts root (target) both work.
  --defer                      Read the parents this run does not select from
                               the relations of the --state manifest instead
                               of this target's, so a dev run of one model
                               reads the production tables. Needs --state.
                               Refused for unit invocations and the task
                               boundary (PLX111).
  --log-format [text|json]     Diagnostics and events on stderr: readable text
                               or one JSON object per line.  [default: text]
  --manifest FILE              Run the plan of this manifest instead of
                               compiling the project.
  --expect-plan-hash HEX       Stop with PLX103 unless the plan hash is this
                               sha256.
  --run-id TEXT                Name of the run. Reusing it continues that run.
                               Default: a timestamp and a suffix.
  --full-refresh BOOLEAN       Rebuild append tables from scratch. Takes an
                               optional true or false.  [default: False]
  --run-started-at ISO8601     Start time of the run, with a UTC offset (for
                               example the start of the orchestrator job).
                               Engines use it to make writes idempotent. Needs
                               --run-id. A reused run id keeps the start it
                               recorded.
  --orchestrator-id KEY=VALUE  An id the orchestrator gave this run, such as
                               job_run_id=42. It goes into the attempt files,
                               the run results and the context of every event.
                               Repeatable; a later duplicate wins. Key:
                               [a-z][a-z0-9_]{0,63}; value: 1 to 256 printable
                               characters.
  --fail-fast                  After the first failure, start no more units.
  --no-lock                    Do not take the run lock.
  --workers INTEGER RANGE      Units to run at once. Default: the target's
                               setting, else min(4, CPUs).  [x>=1]
  --boundary [process|task]    process runs units on threads here; task runs
                               each in its own process. Default: the target's
                               boundary.
  --warn-error                 Exit 1 on warnings too.
  --cancel-grace DURATION      After a stop request (Ctrl+C, SIGTERM) or a
                               timeout, how long running units may finish
                               before they are killed, as 30s, 2m or 30.
                               Default: the setting, else 30s.
  --help                       Show this message and exit.
