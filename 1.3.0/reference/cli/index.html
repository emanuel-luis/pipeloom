    pipeloom init¶

    pipeloom init [DIRECTORY] creates a project, like dbt init. DIRECTORY defaults to a new folder named after the project in the current directory.

    • When stdin is a terminal it asks for what the flags leave out: the project name (default: the directory name), the engine (polars, pandas, spark, databricks or duckdb, default polars; the default stays polars) and, on databricks, the Unity Catalog catalog (default main). Otherwise, or with --no-input, it uses the flags and those defaults.
    • Each layer folder, models/bronze, models/silver and models/gold, gets one .py file with a decorated model. polars, spark and databricks models return ctx.sql(...); pandas models are frame code, since pandas runs SQL only with the optional DuckDB extra. pipeloom.yml holds the source group raw and a models: tree that sets each layer's schema and tags; models/silver/_properties.yml holds a description. .vscode/settings.json maps project.json to pipeloom.yml and properties.json to models/**/*.yml. polars, pandas and spark read a small CSV in data/, so pipeloom run works right away on polars and pandas. databricks reads samples.tpch.orders and comes with a state table, an artifacts volume and a serverless deploy block; the comments in pipeloom.yml say what to create before pipeloom databricks deploy.
    • A directory that is not empty needs --force. Existing files are never overwritten: they are kept and listed as skipped. A directory that already holds pipeloom.yml is refused.
    • It also writes AGENTS.md and three skills under .agents/skills/, generated from the code (the command list and the diagnostic catalog); see Working with coding agents. --update-agents rewrites just those files in the project at DIRECTORY (default: the current directory) and takes no other option except --log-format.
    • Exit codes: 0 on success, 2 on a usage error (bad name or engine, --catalog without databricks, an existing project, a non-empty directory without --force).

    pipeloom demo¶

    pipeloom demo [DIRECTORY] is the quickest way to see pipeloom work. It writes the init project for the duckdb engine into DIRECTORY (default pipeloom_demo in the current directory), runs pipeloom build on it (a unit test, three models and their data tests), writes the docs site and prints where it is and what to try next.

    • It needs the DuckDB engine (pip install "pipeloom[duckdb]"). Without it the command stops with PLU004 and the install command as the hint. It never falls back to another engine, so the demo is the same on every machine.
    • DIRECTORY must be missing or empty. The site is DIRECTORY/target/docs/index.html.
    • Exit codes: 0 on success, 1 when the engine is missing or the build fails, 2 for a directory that is not empty.

    pipeloom new model¶

    pipeloom new model NAME adds one model file to a project and prints its path.

    • The file is models/<folder>/<NAME>.py, with one function NAME decorated with @model. --folder is relative to the first model path and cannot leave it.
    • --sql writes a body that returns ctx.sql("select 1 as id"). --python writes a frame stub that raises NotImplementedError until you write the body. Without a flag, pandas default targets get --python and the rest --sql. Add one parameter per input, named like the model or source table it reads.
    • Exit codes: 0 on success, 1 when the project does not load, 2 on a usage error (bad name, a Python keyword or ctx, model or ModelContext as the name, a model or file that exists, --sql with --python, a folder outside the model path, a file outside every python_paths root, or a name that is already a folder where the file would go, such as bronze in an init project).

    Machine-readable output¶

    Every command takes --log-format json (or PIPELOOM_LOG_FORMAT=json): stderr then carries one pipeloom.event/1 object per line. A diagnostic event has an optional explain_url, the link to the code's entry on the error-code page. pipeloom compile --output json prints a pipeloom.compile_result/1 object (manifest path and hash, plan counts) instead of the bare path. pipeloom plan --diff --output json prints a pipeloom.plan_diff/1 object (the change category of each changed model). pipeloom init writes AGENTS.md and skills under .agents/skills/, and pipeloom init --update-agents [DIRECTORY] regenerates only those files in an existing project.

    pipeloom backfill¶

    Run the selected interval models over [--start, --end).

    Each model runs the windows of its own grain that overlap the range, clipped to its begin and to the run's start, through the same path as run: one token per window, and the ledger records each window it writes. Rerunning the same backfill runs only what is missing. Models without incremental.interval run as in run when selected (with + for descendants); a selection with no interval model is PLX132. Takes the run flags except --full-refresh, --manifest, --state and --defer. Exit codes: 0 ok, 1 a window or a unit failed, 2 bad usage, 130 stopped.

    Usage:

    pipeloom backfill [OPTIONS]

    Options:

      --project-dir DIRECTORY       Directory that holds pipeloom.yml.  [default:
                                .]
  --vars TEXT                   Variables as a YAML or JSON mapping; they
                                override the vars block.
  --target TEXT                 Target to bind; default_target or the only
                                target when omitted.
  --plugin MODULE:ATTR          A PluginSpec to load besides the installed
                                plugins. Repeatable.
  -s, --select SELECTOR         Models to include: name, tag:x, path:dir,
                                materialized:x, +model, model+, N+model,
                                model+N. Space unions, comma intersects.
                                Repeatable, all are unioned.
  --exclude SELECTOR            Remove the models this selector matches from
                                the selection. Repeatable.
  --log-format [text|json]      Diagnostics and events on stderr: readable
                                text or one JSON object per line.  [default:
                                text]
  --run-id TEXT                 Name of the run. Reusing it continues that
                                run. Default: a timestamp and a suffix.
  --run-started-at ISO8601      Start time of the run, with a UTC offset (for

  --mark-done                   Record the range in the ledger exactly as

  --help                        Show this message and exit.

    pipeloom build¶

    Run the unit tests of the selected models, then run them with data tests.

    Any failed unit test stops the build with exit 1 before a run id exists and before any write. Each model's data tests then run after its write; a failed one (PLQ303) fails the unit, skips its descendants and leaves the data written. Takes the flags of run. Exit codes: 0 ok, 1 a unit test, a unit or a check failed, 2 bad usage, 130 stopped.

    Usage:

    pipeloom build [OPTIONS]

    Options:

      --project-dir DIRECTORY      Directory that holds pipeloom.yml.  [default:
                               .]
  --vars TEXT                  Variables as a YAML or JSON mapping; they
                               override the vars block.
  --target TEXT                Target to bind; default_target or the only
                               target when omitted.
  --plugin MODULE:ATTR         A PluginSpec to load besides the installed
                               plugins. Repeatable.
  -s, --select SELECTOR        Models to include: name, tag:x, path:dir,
                               materialized:x, +model, model+, N+model,
                               model+N. Space unions, comma intersects.
                               Repeatable, all are unioned.
  --exclude SELECTOR           Remove the models this selector matches from
                               the selection. Repeatable.
  --state DIR                  Folder of a reference manifest.json (and
                               optionally run_results.json), for the state:
                               and result: selectors. Relative to the project
                               dir unless absolute. `compile --stable` or the
                               artifacts root (target) both work.
  --defer                      Read the parents this run does not select from
                               the relations of the --state manifest instead
                               of this target's, so a dev run of one model
                               reads the production tables. Needs --state.
                               Refused for unit invocations and the task
                               boundary (PLX111).
  --log-format [text|json]     Diagnostics and events on stderr: readable text
                               or one JSON object per line.  [default: text]
  --manifest FILE              Run the plan of this manifest instead of
                               compiling the project.
  --expect-plan-hash HEX       Stop with PLX103 unless the plan hash is this

  --run-id TEXT                Name of the run. Reusing it continues that run.

  --full-refresh BOOLEAN       Rebuild append tables from scratch. Takes an

                               example the start of the orchestrator job).
                               Engines use it to make writes idempotent. Needs
                               --run-id. A reused run id keeps the start it
                               recorded.
  --orchestrator-id KEY=VALUE  An id the orchestrator gave this run, such as
                               job_run_id=42. It goes into the attempt files,
                               the run results and the context of every event.
                               Repeatable; a later duplicate wins. Key:
                               [a-z][a-z0-9_]{0,63}; value: 1 to 256 printable
                               characters.
  --fail-fast                  After the first failure, start no more units.
  --no-lock                    Do not take the run lock.
  --workers INTEGER RANGE      Units to run at once. Default: the target's
                               setting, else min(4, CPUs).  [x>=1]
  --boundary [process|task]    process runs units on threads here; task runs
                               each in its own process. Default: the target's
                               boundary.
  --warn-error                 Exit 1 on warnings too.
  --cancel-grace DURATION      After a stop request (Ctrl+C, SIGTERM) or a
                               timeout, how long running units may finish
                               before they are killed, as 30s, 2m or 30.
                               Default: the setting, else 30s.
  --help                       Show this message and exit.

    pipeloom diff¶

    Compare MODEL's relation in the --state reference with its relation on this target.

    Rows are matched by key and compared column by column, nulls equal to nulls. Without --samples the output holds counts and the schema diff, never a cell value. Exit codes: 0 no differences, 1 differences or a failure, 2 usage error.

    Usage:

    pipeloom diff [OPTIONS] MODEL

    Options:

      --project-dir DIRECTORY   Directory that holds pipeloom.yml.  [default: .]
  --vars TEXT               Variables as a YAML or JSON mapping; they override
                            the vars block.
  --target TEXT             Target to bind; default_target or the only target
                            when omitted.
  --plugin MODULE:ATTR      A PluginSpec to load besides the installed
                            plugins. Repeatable.
  --state DIR               Folder of the reference manifest.json, whose
                            relation of MODEL is the source side. Relative to
                            the project dir unless absolute.  [required]
  --key COLUMN              Key column; repeatable. Default: the model's
                            write.unique_key.
  --samples                 Add up to 10 rows per kind of difference. Columns
                            tagged sensitive are masked.
  --output [markdown|json]  Markdown for a pull request comment, or the
                            pipeloom.table_diff/1 document.  [default:
                            markdown]
  --log-format [text|json]  Diagnostics and events on stderr: readable text or
                            one JSON object per line.  [default: text]
  --help                    Show this message and exit.

    pipeloom finalize¶

    Merge the unit results of a run into run_results.json and close the run.

    Units in scope (default: the whole plan) take their attempt file, else the state given with --unit-states or --unit-states-json, else they are skipped as not_run, which does not fail the run. A unit marked excluded gets no row. Exit codes: 0 ok, 1 a unit failed, 2 bad usage, 130 cancelled. Running it again rewrites the same results.

    Usage:

    pipeloom finalize [OPTIONS]

    Options:

      --project-dir DIRECTORY      Directory that holds pipeloom.yml.  [default:
                               .]
  --vars TEXT                  Variables as a YAML or JSON mapping; they
                               override the vars block.
  --target TEXT                Target to bind; default_target or the only
                               target when omitted.
  --plugin MODULE:ATTR         A PluginSpec to load besides the installed
                               plugins. Repeatable.
  -s, --select SELECTOR        Models to include: name, tag:x, path:dir,
                               materialized:x, +model, model+, N+model,
                               model+N. Space unions, comma intersects.
                               Repeatable, all are unioned.
  --exclude SELECTOR           Remove the models this selector matches from
                               the selection. Repeatable.
  --log-format [text|json]     Diagnostics and events on stderr: readable text
                               or one JSON object per line.  [default: text]
  --run-id TEXT                The run to close: the run id every unit
                               invocation used.  [required]
  --manifest FILE              Use the plan of this manifest instead of
                               compiling the project.
  --expect-plan-hash HEX       Stop with PLX103 unless the plan hash is this
                               sha256.
  --unit-states PATH           A JSON file, schema pipeloom.unit_states/1,
                               with what the orchestrator knows about units
                               that wrote no attempt file: {unit_id: {status:
                               skipped|cancelled|failed|excluded, reason,
                               code, message, orchestrator_ids}}.
  --unit-states-json TEXT      The same document as --unit-states, given
                               inline (for an orchestrator that cannot share a
                               file). Not together with --unit-states.
  --orchestrator-id KEY=VALUE  An id the orchestrator gave this run, such as
                               job_run_id=42. It goes into the attempt files,
                               the run results and the context of every event.
                               Repeatable; a later duplicate wins. Key:
                               [a-z][a-z0-9_]{0,63}; value: 1 to 256 printable
                               characters.
  --run-started-at ISO8601     Start time of the run, with a UTC offset. A run
                               that recorded its start keeps it.
  --help                       Show this message and exit.

    pipeloom init¶

    Create a project in DIRECTORY (default: a new folder named after the project).

    When stdin is a terminal and --no-input is not given, asks for the values the flags leave out: the project name, the engine and, on databricks, the catalog. Also writes AGENTS.md and skills under .agents/skills/, generated from the code and never fetched.

    Usage:

    pipeloom init [OPTIONS] [DIRECTORY]

    Options:

      --name TEXT                     Project name. Default: the directory name.
  --engine [polars|pandas|spark|databricks|duckdb]
                                  Engine of the dev target. Default: polars.
  --catalog TEXT                  Unity Catalog catalog of the dev target

                                  defaults.
  --force                         Allow a directory that is not empty.
                                  Existing files are kept, never overwritten,

    pipeloom retry¶

    Run again what a finished run did not finish. Exit codes as run; 1 also for PLX113.

    Selects the units of run RUN_ID that failed, timed out, were skipped or were cancelled, and runs them in a new run that records RUN_ID as its parent. The project is compiled again, so a fixed model is picked up. The retry inherits the vars (--vars wins), --full-refresh, --state and --defer of the run it retries.

    Usage:

    pipeloom retry [OPTIONS]

    Options:

      --project-dir DIRECTORY         Directory that holds pipeloom.yml.
                                  [default: .]
  --vars TEXT                     Variables as a YAML or JSON mapping; they
                                  override the vars block.
  --target TEXT                   Target to bind; default_target or the only
                                  target when omitted.
  --plugin MODULE:ATTR            A PluginSpec to load besides the installed
                                  plugins. Repeatable.
  --log-format [text|json]        Diagnostics and events on stderr: readable
                                  text or one JSON object per line.  [default:
                                  text]
  --from RUN_ID                   The finished run to retry: its failed,
                                  skipped and cancelled units run again.
                                  [required]
  --run-id TEXT                   Name of the new run; it must differ from
                                  --from. Default: a timestamp and a suffix.
  --full-refresh / --no-full-refresh
                                  Rebuild append tables from scratch. Default:
                                  what the retried run did.
  --orchestrator-id KEY=VALUE     An id the orchestrator gave this run, such
                                  as job_run_id=42. It goes into the attempt
                                  files, the run results and the context of
                                  every event. Repeatable; a later duplicate
                                  wins. Key: [a-z][a-z0-9_]{0,63}; value: 1 to
                                  256 printable characters.
  --fail-fast                     After the first failure, start no more
                                  units.
  --no-lock                       Do not take the run lock.
  --workers INTEGER RANGE         Units to run at once. Default: the target's
                                  setting, else min(4, CPUs).  [x>=1]
  --boundary [process|task]       process runs units on threads here; task
                                  runs each in its own process. Default: the
                                  target's boundary.
  --warn-error                    Exit 1 on warnings too.
  --cancel-grace DURATION         After a stop request (Ctrl+C, SIGTERM) or a
                                  timeout, how long running units may finish
                                  before they are killed, as 30s, 2m or 30.
                                  Default: the setting, else 30s.
  --help                          Show this message and exit.

    pipeloom run¶

    Run the selected models. Exit codes: 0 ok, 1 a unit or a check failed, 2 bad usage, 130 stopped.

    The first Ctrl+C or SIGTERM stops starting units and gives running ones --cancel-grace to finish; a second one kills them at once; a third raises KeyboardInterrupt.

    -s unit:NAME runs one unit without a lock or run results, and never retries it; the process executor uses it.

    Usage:

    pipeloom run [OPTIONS]

    Options:

      --project-dir DIRECTORY      Directory that holds pipeloom.yml.  [default:
                               .]
  --vars TEXT                  Variables as a YAML or JSON mapping; they
                               override the vars block.
  --target TEXT                Target to bind; default_target or the only
                               target when omitted.
  --plugin MODULE:ATTR         A PluginSpec to load besides the installed
                               plugins. Repeatable.
  -s, --select SELECTOR        Models to include: name, tag:x, path:dir,
                               materialized:x, +model, model+, N+model,
                               model+N. Space unions, comma intersects.
                               Repeatable, all are unioned.
  --exclude SELECTOR           Remove the models this selector matches from
                               the selection. Repeatable.
  --state DIR                  Folder of a reference manifest.json (and
                               optionally run_results.json), for the state:
                               and result: selectors. Relative to the project
                               dir unless absolute. `compile --stable` or the
                               artifacts root (target) both work.
  --defer                      Read the parents this run does not select from
                               the relations of the --state manifest instead
                               of this target's, so a dev run of one model
                               reads the production tables. Needs --state.
                               Refused for unit invocations and the task
                               boundary (PLX111).
  --log-format [text|json]     Diagnostics and events on stderr: readable text
                               or one JSON object per line.  [default: text]
  --manifest FILE              Run the plan of this manifest instead of
                               compiling the project.
  --expect-plan-hash HEX       Stop with PLX103 unless the plan hash is this
                               sha256.
  --run-id TEXT                Name of the run. Reusing it continues that run.
                               Default: a timestamp and a suffix.
  --full-refresh BOOLEAN       Rebuild append tables from scratch. Takes an
                               optional true or false.  [default: False]
  --run-started-at ISO8601     Start time of the run, with a UTC offset (for
                               example the start of the orchestrator job).
                               Engines use it to make writes idempotent. Needs
                               --run-id. A reused run id keeps the start it
                               recorded.
  --orchestrator-id KEY=VALUE  An id the orchestrator gave this run, such as
                               job_run_id=42. It goes into the attempt files,
                               the run results and the context of every event.
                               Repeatable; a later duplicate wins. Key:
                               [a-z][a-z0-9_]{0,63}; value: 1 to 256 printable
                               characters.
  --fail-fast                  After the first failure, start no more units.
  --no-lock                    Do not take the run lock.
  --workers INTEGER RANGE      Units to run at once. Default: the target's
                               setting, else min(4, CPUs).  [x>=1]
  --boundary [process|task]    process runs units on threads here; task runs
                               each in its own process. Default: the target's
                               boundary.
  --warn-error                 Exit 1 on warnings too.
  --cancel-grace DURATION      After a stop request (Ctrl+C, SIGTERM) or a
                               timeout, how long running units may finish
                               before they are killed, as 30s, 2m or 30.
                               Default: the setting, else 30s.
  --help                       Show this message and exit.
